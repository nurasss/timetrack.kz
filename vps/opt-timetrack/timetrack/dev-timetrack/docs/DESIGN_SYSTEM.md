# Дизайн-система Timetrack

Версия: 1.1  
Дата фиксации: 24 июля 2026 года

Этот документ задаёт единый визуальный язык Timetrack для лендинга, административной панели и следующих интерфейсов продукта. Главный принцип — спокойный функциональный минимализм: интерфейс должен помогать быстро считать состояние системы, не конкурируя с рабочими данными.

## 1. Дизайн-код

Основной характер Timetrack — точный, технологичный и деловой. Визуальная система строится на тёплой светлой нейтральной основе, крупных читаемых заголовках, простых геометрических формах и умеренных скруглениях.

Правила:

- тёплые светлые поверхности, чёрный текст и чёрные основные действия — основа интерфейса;
- синий и зелёный остаются только в фирменном знаке;
- цвет не используется как украшение;
- зелёный, жёлтый и красный применяются только для смысловых статусов;
- главные действия заметнее второстепенных за счёт контраста, а не яркого акцентного цвета;
- декоративные эффекты не должны снижать читаемость или скорость работы.

## 2. Цветовая система

### Основная тёплая нейтральная палитра

| Токен | HEX | Назначение |
|---|---:|---|
| `warm-50` | `#F7F5F1` | Фон страниц |
| `warm-100` | `#F0ECE7` | Вложенные поверхности и таблицы |
| `warm-200` | `#EBE7E2` | Панели, шапка и карточки |
| `warm-300` | `#D5CFC8` | Границы и разделители |
| `ink` | `#1C1C1C` | Основной текст и primary-действия |
| `ink-2` | `#555555` | Вторичный текст |
| `muted` | `#777777` | Подписи и вспомогательный текст |
| `black` | `#000000` | Hover primary-действий и важные ссылки |
| `white` | `#FFFFFF` | Воздушные слои и максимальный контраст |

### Фирменные цвета

| Токен | HEX | Назначение |
|---|---:|---|
| `brand-blue` | `#2563EB` | Синий сегмент логотипа |
| `brand-green` | `#22C55E` | Зелёный сегмент логотипа |

Фирменные цвета не заменяют основную палитру интерфейса. Они используются в логотипе, favicon и PWA-иконке, чтобы бренд оставался узнаваемым даже в монохромном окружении.

### Семантические цвета

| Состояние | Основной цвет | Применение |
|---|---:|---|
| Успех | `#167A46` | Успешная синхронизация, подтверждение |
| Предупреждение | `#8A5D00` | Опоздание, ручная проверка |
| Ошибка | `#C24147` | Ошибка, удаление, критичное действие |

Семантический цвет всегда сопровождается текстом или иконкой. Нельзя передавать состояние только цветом.

## 3. Цветовые сочетания

Для административной панели:

- фон страницы: `#F7F5F1`;
- поверхность: `#EBE7E2`;
- вложенная поверхность: `#F0ECE7`;
- граница: `#D5CFC8`;
- основной текст: `#1C1C1C`;
- вторичный текст: `#555555`;
- primary-кнопка: фон `#1C1C1C`, текст `#F7F5F1`;
- hover primary-кнопки: фон `#000000`, текст `#F7F5F1`.

Для лендинга используется та же система:

- основной текст и важные текстовые ссылки: `#000000` или `#1C1C1C`;
- фоновая основа: `#F7F5F1`;
- крупные секции: `#EBE7E2`;
- карточки второго уровня: `#F0ECE7`;
- вторичный текст: `#555555`.

Минимальный контраст обычного текста — 4.5:1, крупного текста и значимых контролов — 3:1.

## 4. Типографика

Основной шрифт — `Roboto`. Системный fallback:

```css
font-family: "Roboto", Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
```

Шкала:

| Роль | Размер | Начертание |
|---|---:|---:|
| Hero | 48–72 px | 700–900 |
| Заголовок страницы | 24–34 px | 700–800 |
| Заголовок секции | 18–24 px | 700 |
| Основной текст | 14–16 px | 400–500 |
| Подпись | 12–13 px | 400–600 |
| Кнопка | 14–16 px | 700 |

Заголовки могут иметь отрицательный `letter-spacing` до `-0.03em`. Основной текст должен сохранять нормальную плотность и межстрочный интервал не менее 1.4.

## 5. Сетка и интервалы

Базовый модуль — 4 px. Рекомендуемый ряд интервалов:

`4, 8, 12, 16, 20, 24, 32, 40, 48, 64`.

- максимальная ширина лендинга: 1280 px;
- максимальная ширина админки: 1240 px;
- desktop-поля контейнера: 24 px;
- mobile-поля: 14–16 px;
- расстояние между связанными элементами: 8–12 px;
- расстояние между смысловыми группами: 24–40 px.

## 6. Геометрия и эффекты

- стандартный радиус контролов админки: 8 px;
- крупные карточки лендинга: 20–24 px;
- мобильная нижняя навигация: до 22 px;
- тень используется только для отделения слоя: `0 16px 40px rgba(0, 0, 0, 0.08)`;
- границы предпочтительнее тяжёлых теней;
- blur допустим только для плавающих слоёв и не должен ухудшать производительность.

## 7. Компоненты

### Кнопки

- `Primary`: чёрная заливка на светлом фоне, светлый текст;
- `Secondary/Ghost`: прозрачная или тёплая светлая поверхность с нейтральной границей;
- `Danger`: красный текст и приглушённая красная поверхность;
- минимальная высота desktop-кнопки — 38 px;
- минимальная удобная зона касания на mobile — 44×44 px.

### Формы

- input и select используют поверхность `#EBE7E2` и границу `#D5CFC8`;
- focus обозначается видимой рамкой с контрастом не ниже 3:1;
- placeholder визуально слабее введённого значения;
- ошибка показывается рядом с полем текстом, а не только красной границей.

### Карточки и таблицы

- карточка не должна иметь более двух вложенных визуальных уровней;
- заголовки таблиц располагаются на поверхности `#F0ECE7`;
- строки разделяются границей `#D5CFC8`;
- числовые показатели используют tabular numbers;
- статусы оформляются badge-компонентами с текстовой подписью.

### Иконки и логотип

- интерфейсные иконки — линейные, единая толщина штриха;
- типовые размеры: 16, 20 и 24 px;
- favicon и PWA-иконка используют фирменный круговой знак из `landing-favicon.svg`;
- логотип нельзя растягивать непропорционально или перекрашивать частично;
- в светлой админке используется исходный цветной знак с чёрным написанием бренда.

## 8. Анимация

- стандартная длительность: 150–220 мс;
- допустимые свойства: `opacity`, `transform`, `background-color`, `color`;
- анимация не должна задерживать выполнение действия;
- необходимо учитывать `prefers-reduced-motion`;
- бесконечные декоративные анимации в рабочих экранах запрещены.

## 9. Адаптивность

- ключевые breakpoint: 1200, 900 и 760 px;
- таблицы на узких экранах превращаются в карточки или получают безопасный горизонтальный scroll;
- основные действия остаются доступны без hover;
- нижняя mobile-навигация не перекрывает контент и учитывает `safe-area-inset-bottom`;
- размер текста не должен требовать zoom для чтения.

## 10. Доступность и контроль качества

Перед релизом интерфейса проверяются:

1. клавиатурная навигация и видимый focus;
2. контраст текста, кнопок и границ;
3. корректные подписи полей и `aria-label` для иконок;
4. состояния loading, empty, error и success;
5. desktop и mobile layout;
6. светлая и тёмная системная панель браузера;
7. favicon, manifest и PWA install prompt;
8. отсутствие цветовых значений вне токенов без обоснованного исключения.

## 11. CSS-токены административной панели

```css
:root {
  color-scheme: light;
  --page: #f7f5f1;
  --surface: #ebe7e2;
  --surface-2: #f0ece7;
  --ink: #1c1c1c;
  --muted: #555555;
  --line: #d5cfc8;
  --brand: #1c1c1c;
  --brand-2: #000000;
  --avatar-bg: #f0ece7;
  --ok: #167a46;
  --warn: #8a5d00;
  --danger: #c24147;
}
```

Новые компоненты должны использовать эти токены вместо локальных оттенков. Изменение палитры начинается с обновления токенов, а не с массовой замены отдельных CSS-правил.
