## Проверки

На рабочем сайте, в штатном Tag Assistant, выполнены отдельные клики:

| Действие | События на одно действие |
| --- | --- |
| Получить консультацию | один `wa_click` |
| Телефон +77009111213 | один `tel_click` |
| Подключить тариф | один `tariff_click` и один `wa_click` |
| 14 дней бесплатно | один `trial_click` |

В [Tag Assistant](tag-assistant-clicks.png) найдены оба тега:
`G-3XSE2HFZ45` и `AW-1011683356`. Два `wa_click` в общей истории соответствуют
двум разным кликам — консультации и подключению тарифа, а не дублю.

Реально создана тестовая компания **analytics-test-20261005**:
- API регистрации вернул HTTP 200 и успешный результат.
- После ответа сервера был вызван один `register_success`.
- Запрос GA4 с этим событием получил HTTP 204, запрос Метрики — HTTP 200.
- На сервере в `marketing` сохранены `utm_source`, `utm_medium`, `utm_campaign`,
  `utm_term`, `utm_content`, `gclid`, `yclid`, перенесённые с главной страницы.
- [Экран успешного создания компании](registration-success.png).

Отдельного скриншота `register_success` в Tag Assistant нет: регистрация была
выполнена до подключения этой сессии отладки. Пользователь решил, что первой
реальной проверки достаточно, и отказался от создания второй тестовой компании.
Подтверждение email и последующий вход в тестовую компанию отдельно не проверены.

Проверено в чистом браузерном контексте: конфигурации GA4 и Ads создаются по
одному разу; есть запросы Ads `/ccm/collect` и `/ccm/s/collect`; ошибок CSP нет.
Локальная проверка JS подтвердила один загрузчик и обработчик при повторном
подключении скрипта, явный адресат GA4 и отсутствие прямых Ads-конверсий.

## Публикация

Рабочий домен указывает на **194.238.42.177**, а не на старый хостинг 195.210.46.53.
Активные статические файлы: `/opt/timetrack/dev-timetrack/public`.
Активная конфигурация HTTP-заголовков: `/opt/timetrack/Caddyfile`.
Деплой выполнен точечными изменениями существующих серверных файлов.
Архивные файлы VPS в репозитории не использовались для полной замены рабочего сайта.

Резервные копии:
- `/opt/timetrack/dev-timetrack/backup-ga4-20261005T072109Z`.
- `/opt/timetrack/dev-timetrack/backup-google-ads-20261005T084953Z`.

В CSP добавлены фактически используемые адреса Google Analytics, Google Ads,
DoubleClick и Tag Assistant. Для публичных страниц входа/регистрации и главной
с явным параметром `gtm_debug` разрешено соединение с окном Tag Assistant;
на обычных страницах и в админке сохраняется `Cross-Origin-Opener-Policy: same-origin`.
Конфигурация Caddy прошла `validate` и применена через `reload`.
